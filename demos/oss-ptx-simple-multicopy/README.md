# Real OSS PTX direct edit: NVIDIA simpleMultiCopy

This demo uses the actual `incKernel` from NVIDIA CUDA Samples, built as its
complete unmodified upstream translation unit with normal Release CMake flags.
The direct PTX edit collapses five repeated load/add/store operations into one
under the normal default repeat count5 and disjoint allocation conditions.

**Accepted direct universal Lean equivalence** via independent kernel replay and
transitive axiom audit: [proof.json](results/proof.json). GPU tests
passed2016 cases. Small cache-hot shapes improve up to about1.35×, but the
normal default shape regresses to0.965×. The predeclared default-shape1.10×
success target failed. Matching restrict CUDA is essentially equally fast.
No sample end-to-end or production application speedup is claimed.

## Reproduction

Requires Linux, CUDA nvcc/ptxas13.2.51, A10G sm_86, driver595.112.07,
Lean4.35.0, Rust/Cargo, CMake and Python3.12. Large state goes to the dedicated
scratch path; Rust builds use release and at most2 jobs. The scripts use the
same GPU lock as other workers and reject foreign compute processes. They do
not change clocks or terminate processes.

```sh
bash demos/oss-ptx-simple-multicopy/run.sh setup
bash demos/oss-ptx-simple-multicopy/run.sh build-upstream
python3 demos/oss-ptx-simple-multicopy/author-edit.py
bash demos/oss-ptx-simple-multicopy/run.sh proof
bash demos/oss-ptx-simple-multicopy/run.sh negative
bash demos/oss-ptx-simple-multicopy/run.sh test
bash demos/oss-ptx-simple-multicopy/run.sh benchmark
python3 demos/oss-ptx-simple-multicopy/report.py
python3 demos/oss-ptx-simple-multicopy/verify-freeze.py
```

The frozen PTX contains upstream absolute `.file` paths from the original normal
build. A rebuild at a different scratch root can change those path bytes/hash;
it must not silently replace the proof subject. Reproduce with the stated root,
or treat new PTX as a new frozen artifact and rebind/reprove it. No CUDA body,
optimization level, dispatch specialization or bounds were weakened for this demo.

## Provenance and performance scope

[freeze.json](freeze.json) binds full source, normal CMake settings/license and
original PTX before editing. The source is
[NVIDIA CUDA Samples at the pinned commit](https://github.com/NVIDIA/cuda-samples/blob/0ec046d5e99d7214cc8e9fbac2cc1e66f3019878/cpp/0_Introduction/simpleMultiCopy/simpleMultiCopy.cu#L58).
Source lines58-67 define the kernel,88-94 set N/repeats/block,174/178 allocate
separate buffers, and192/212/316 launch the same implementation. There is no
alternate tuned upstream dispatch. [upstream](upstream) retains BSD-3-Clause
notice, complete TU, CMakeLists and actual flags. `--keep` only retains compiler
artifacts. No extraction wrapper was needed. Normal upstream executable success
is retained in [upstream-run.txt](results/upstream-run.txt).

The kernel intentionally supplies repeated compute work for a stream/copy
illustration. Output equivalence does not preserve that workload's duration.
Read [SCREENING.md](SCREENING.md) for the other practical targets assessed and
this selection's limitation. The [protocol](PROTOCOL.md) predates candidate
editing; the AOT follow-up is separately declared there. [MEASUREMENTS.md](MEASUREMENTS.md)
reports all shapes, including regressions. [Raw data](results/performance.json)
contains normal-build cubin, same-ptxas edit/tuned cubins and all driver-JIT
variants. API allocation, host transfers and sample multi-stream overlap are
outside these kernel-only timings. The first JIT-only dataset is also retained.

The matching [tuned CUDA](tuned.cu) changes only the two pointer declarations to
restrict. It is an author written comparator, not an alternate upstream kernel.
The original normal allocations already satisfy nonalias. The actual candidate
is [edited.ptx](edited.ptx), authored from [original.ptx](original.ptx) by the
inspectable PTX text edit [author-edit.py](author-edit.py), never generated by
compiling candidate CUDA. Redundant work was present in normal optimized PTX.

## Exact theorem and limitations

The statement is generated from both PTX texts and [equivalence.json](equivalence.json),
using `Ptx.Auto.OssInc.Spec.Equivalent`. The domain contains launch/allocation
conditions only, with no mathematical output specification. The proof relates
the original's concrete final memory directly to the candidate's concrete final
memory. An input-read frame lemma and repeated-store idempotence justify removal.
The existing relational framework lifts solo traces to every independent pair
of completed interleavings, including all global bytes outside the output.

Allowed inputs: every n<2^31, one-dimensional G/B with n≤G*B≤2^31, fixed
inner_reps5 (actual normal default), aligned4, nonwrapping disjoint n-word
input/output allocations. Every initial global byte, thread register/predicate
and shared memory value is quantified. n0, arbitrary tails, all32-bit input
patterns and modular increment overflow are included. Both sides must be safe,
race free, make progress, have bounded executions and an actual completed run.
Parameters fix only the declared values; there is no hidden assumption about
initial outputs. Physical CUDA launch bounds apply in the GPU adapter.

The normal upstream grid formula supports the default shape but is not a general
tail dispatcher. The demo uses ceiling-grid for additional tail/large shapes,
explicitly as a generalized launch adapter with the unchanged kernel body.
The theorem does not cover other repeat counts or overlapping allocations.
The GPU alias witness gives original5 versus edited1, confirming this exclusion
is essential. The CUDA source uses signed int; adversarial overflow tests concern
frozen PTX modular arithmetic, not a proof of defined CUDA C++ signed-overflow
behavior. All timed inputs avoid signed overflow.

Accepted evidence requires independent replay of every supplied declaration and
transitive axiom audit, allowing only propext, Quot.sound and Classical.choice.
Exact original/candidate/contract hashes and Lean version bind the proof/checker.
No sorry, extra axiom, native_decide or bv_decide is permitted. Hash-rebound
semantic negatives are separate from stale-hash rejection. GPU/NumPy tests do
not prove universality. Rust parsing/export, NVIDIA CUDA-to-PTX compilation,
ptxas/driver JIT/SASS and hardware correspondence remain outside the Lean theorem.

## Frontend additions and dependencies

Normal nvcc output required `.file`, `.loc`, `.pragma "nounroll"` and `or.pred`.
The original parser errors are retained. Metadata is validated with narrow
syntax and retained in exact token roundtrip; it does not create execution PCs
or alter labels. Unknown directives/attributes/pragmas remain rejected.
`or.pred` has explicit Boolean execution semantics in Rust and Lean, with typed
predicate operands. [Frontend evidence](results/frontend-tests.txt),
[Lean truth/guard/frame checks](results/por-lean.txt) and
[GPU truth table](results/por-gpu.json) distinguish the validation layers.
The semantics follow [NVIDIA's PTX or documentation](https://docs.nvidia.com/cuda/archive/13.0.3/parallel-thread-execution/index.html#logic-and-shift-instructions-or).

Published `origin/verified-ptx-demo` commit16cbf0d (including ccfec80 direct
relational checker and2f386ea stencil work) was fast-forwarded as a dependency.
Imported project-authored baselines/results are not this worker's OSS results.
No other worktree or uncommitted candidate was copied. New results live only
under this directory. The narrow new domain reuses the published allocation
lemmas and relational lifting, with no checker/audit bypass.
