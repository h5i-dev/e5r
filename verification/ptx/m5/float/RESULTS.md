# M5, float part (NVIDIA A10G)

Generated by `report_float.py`. The 22 tasks in `tasks.json` were written by the agent (Claude, an LLM)
in one pass before any was checked: 16 meant to be correct and 6 with a seeded defect. 21 kernels share
one skeleton (`write_kernels.py`: index, bound check, loads, the task's instruction lines, store); the
grid-stride `f_saxpy_stride.ptx` is written by hand. Specs (`mkspec.py`) state each output element as an
expression of the model's float operations, bit-exact up to NaN payloads.

The GPU test runs each kernel and a CUDA C baseline (nvcc -O3, the intrinsic of the same rounding:
`__fmaf_rn`, `__fdiv_rn`, ...; `-ftz=true` where the task flushes) on the same inputs (edge values,
random bit patterns, random normal numbers), 133,094 elements per task (199,641 for the stride kernel),
and requires equal bits, any NaN matching any NaN. The baseline does not use the Lean model.

- Lean proof time per proved kernel: median 4.1 s, max 10.3 s (one Lean thread).
- All 16 proved kernels agree with the baseline on the GPU; 6 of 6 seeded kernels differ from theirs.
- Speed, baseline time / PTX time at 2^24 elements: median 1.00 (0.98 to 1.02).
- The fix after the first run: `fbug_axpy_fused` (an fma where the spec rounds the product first) was
  `unknown` because the counterexample search tried 44 small launches of random bit patterns and found
  no input where the two roundings differ. The search now also draws normal numbers of nearby
  magnitude and tries 2000 one-element launches for float maps; it then found one (replayed in Lean).
- `fbug_div_approx` uses `div.approx.f32`, which the model refuses (no exact specification).
